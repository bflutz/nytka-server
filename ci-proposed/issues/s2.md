# BMain endpoints: speech-to-text, LLM and embeddings on configurable LAN URLs, no cloud by default

Phase 1 ([plan](https://github.com/bflutz/nytka-server/blob/phase1/docs/voice-recorder-plan.md), §4). Speech-to-text and the language model run on BMain, Barend's Windows PC with an RTX 4070 Ti SUPER. STT is speaches/faster-whisper large-v3 on `http://<bmain>:8000/v1/audio/transcriptions`; the LLM and embeddings use Ollama's OpenAI-compatible API on `http://<bmain>:11434/v1`. The fallback LLM is Homley's CT 110 llama.cpp, `http://192.168.50.52:8080/v1`. Nytka already reads `Nytka__Stt__Url` and the LLM base URL (configuration.md lines 25-46). This issue makes the private-network setup explicit and safe.

**Change:**
- Add a setting `Nytka__Network__AllowPublicEndpoints`, default `false`. With it off, the server refuses to start, with a clear message, if any STT, LLM, embeddings or webhook URL resolves to a non-private address. Allowed: RFC 1918, 100.64.0.0/10 (Tailscale), loopback and `*.ts.net`.
- Make sure no other outbound call runs by default (for example price tables or update checks). List every outbound host in the docs and switch any cloud one off by default.
- Add `docs/how-to/bmain-endpoints.md`. It gives the env lines for speaches and Ollama, the `verbose_json` requirement, the CT 110 fallback and the GPU check (see the server issue 'GPU-use check').

**Done when:**
- Tests: a public STT URL is refused by default and accepted with the setting `true`; private, loopback and Tailscale URLs are accepted.
- The how-to and configuration.md are updated; the build is clean.
