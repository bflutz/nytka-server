# Phone-mic: advertise the `phone-mic` feature and tag uploads by source

Phase 1 of Barend's voice recorder ([plan](https://github.com/bflutz/nytka-server/blob/phase1/docs/voice-recorder-plan.md), R14). The app only shows its phone-microphone switch when the server lists `phone-mic` in `GET /api/v1/info` features (app: `core/.../ApiModels.kt` `FEATURE_PHONE_MIC`). Today the server never lists it, and nothing in `src/` reads an `X-Nytka-Source` header.

**Change:**
- Add `phone-mic` to the features in `/api/v1/info`, behind a setting `Nytka__PhoneMic__Enabled` (default `true`).
- Accept uploads from the phone's microphone the same way as pendant uploads (same Opus/Ogg format, 16 kHz mono).
- Read the app's source header (check the app's upload code for its exact name and values) and store the source per batch, so pendant and phone audio can be told apart. Add a migration if a column is needed.
- Document the setting in `docs/reference/configuration.md`.

**Done when:**
- `/api/v1/info` lists `phone-mic` by default and stops listing it with the setting `false`.
- A test uploads a phone-mic batch and finds it transcribed and stored with source `phone`; a pendant batch still stores as before.
- `dotnet build -c Release` is clean; the new tests pass in ci.yml.
